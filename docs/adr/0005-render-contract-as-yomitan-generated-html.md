# Render contract enforced as Yomitan-generated HTML

The rendered HTML users see is Yomitan's `StructuredContentGenerator` output over our structured content, not our own HTML — so the render contract is enforced at that boundary: bun tests and Storybook play functions both assert on HTML produced by Yomitan's real generator, vendored into `tests/rendered/vendor/` and refreshed by `update:fixture` in the same pass that installs the extension. Assertions are targeted (cheerio/`data-sc-*` queries), not full-document snapshots, so generator upgrades surface as reviewable contract changes rather than snapshot churn.

An HTML→structured-content parser was considered and rejected: rendering is not invertible, so "our SC parses back to the golden HTML" enforces a weaker property than "our SC renders to the golden HTML" — the round trip can silently pass while the real render differs. Golden HTML files were also rejected as the primary mechanism for the same reason (they freeze one generator version's output) and because targeted asserts preserve the existing SC-level assertion power (`data-sc-content`/`data-sc-level` carry the unit structure into the rendered HTML).

Storybook was chosen over a static gallery for the visual layer because each story pairs a displayed entry with a play function that asserts it in a real browser — the displayed artifact and the tested artifact are one. The test runner is the Vitest addon (browser mode, Playwright provider) rather than the legacy Jest test-runner, which current Storybook docs mark as superseded for Vite-based frameworks.
