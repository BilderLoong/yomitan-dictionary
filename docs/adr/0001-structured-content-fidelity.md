# Structured-content fidelity rules

The MWU renderer (`src/conversion/renderStructuredContent.ts`) reproduces source semantics as Yomitan structured content with unit marks (`data-content` values like `called-also`, `comparison-reference`, `relation-reference`) and `level`/`relation`/`sourceMarker` attributes, because Yomitan's structured-content generator only supports a fixed tag set (span, div, ol, li, details, summary, br, table, img, a) and drops unknown tags — semantic information therefore rides on `data-sc-*` attributes, not on HTML tags. Three source-shape rules are deliberate: nested `.un` usage notes are flattened depth-first into separate notes with examples scoped to their owning note; example attributions pair positionally with their own `ex-sent-group` (only the outermost `.aq` per group counts, since MWU nests `<span class="aq">` inside the `ex-sent aq` wrapper); a `.pr` containing or inside `.mw_t_it` is annotation prose kept verbatim, while plain `.pr` segments are phonetic readings wrapped in `/…/`. All styling ships in the ZIP's `styles.css` (Yomitan scopes it to the dictionary); the renderer emits no inline styles. The stylesheet targets only the dictionary's own structured-content units (`[data-sc-content]`); Yomitan's own UI — including the definition-tag chips it renders from the record's definition-tag field — keeps Yomitan's default styling and is never overridden by the dictionary.
