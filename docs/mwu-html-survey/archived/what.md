# Word survey: what

Status: source evidence and hand-authored structured-content design fixture.
This report records the HTML ownership evidence used to write
`packages/merriam_webster_unabridged/design-fixtures/what/term_bank_1.json`.
The fixture is not generated by a parser, and this report is not a claim that
the production converter already supports every unit below.

## Source identity

- word row: id 464223
- HTML length: 65,653 characters
- `<mean>` blocks: 5
- top-level parts of speech: pronoun, adverb, adjective, noun, conjunction
- alt rows: 25
- associated alternate forms include `what and if`, `what an if`, `what
  about`, `what for`, `what have you`, `what if`, `what's with`, `what
  though`, `what time`, and `what way`

The five `<mean>` blocks are separate siblings. Each contains its own header,
pronunciation, origin region, and definition tree, so the fixture creates five
Level 1 `what` records with tags `pron`, `adv`, `adj`, `n`, and `conj`.

## Level 1 evidence

### Headword and part of speech

`.hword` and the header `.fl` identify the local lexical/POS block. The noun
block has a `.headword-row .vg-ins` containing the real text:

    inflected form(s): plural -s

The fixture keeps this as one inline `inflection-group`. Its label and marker
are spans in one line, not separate vertical blocks.

### Pronunciation

Each `.prs` contains two `.pr` readings. The fixture keeps both readings in
one structured-content `pronunciation` node:

    /ˈ(h)wät/ /ˈ(h)wət/

The Yomitan reading field remains empty. Audio controls are source evidence
only and are intentionally ignored for this design fixture.

### Origin

`.section-content.etymology` owns the origin text for the local Level 1
entry. `.toggle .text` / `h2.toggle` supplies the visible title `Origin of
WHAT`. The fixture represents the title as an `origin-section-title` summary
inside a collapsed `details` section, and keeps the etymology text below it.

First Known Use is also present as plain text in some origin sections. It is
catalogued but intentionally ignored for the current dictionary.

## Sense and definition evidence

The definition tree uses `.sb`, `.sense`, `.sn`, `.num`, `.letter`, and
`.sub-num` to express numbered, lettered, and parenthesized markers. The
fixture retains these markers as nested ordered-list structure rather than
manually typing their numbers into definition text.

`.dt` owns the definition text. `.sl` and group-level `.sls > .sl` labels
remain attached to the nearest local definition flow. The conjunction block
provides the real `substandard` label; the phrase `what's with` provides the
real `slang` label. Labels such as `obsolete` remain visually distinct and
inline with their owning definition.

`.un` / `.unText` usage notes remain nested under their local definition. The
`what` source contains this nested note and example:

    —used principally before phrases beginning with with
    what with the drought and a strike in the mine, life is hard

This proves that a usage note may contain another usage-note unit and its own
example. It must not be flattened into the parent definition.

`.dx-jump` comparison text and visible cross-reference text remain attached to
the definition that contains them. Source navigation targets are discarded,
but visible terms are retained. Cross-references such as `1whatever`,
`whoever 1`, and `2whatever` carry small reference numbers; the fixture names
that presentation unit `superscript-reference` and keeps each number beside
its cross-reference.

## Phrase and alternate evidence

`.dro` is a phrase collection. Each `.drp` has its own phrase boundary and
definition tree, so it is a separate searchable Level 1 canonical entry while
the parent `what` entry retains the phrase section.

For `what an if`, the local phrase definition is represented in the parent
phrase section and also as its own canonical entry. The following `.vr`/`.va`
provides the phrase alternative `what and if`; it becomes a
Yomitan dictionary-deinflection soft link to `what an if` rather than a copied
definition. The fixture therefore contains both searchable terms without
duplicating the definition tree.

The alt table is recorded as source-row metadata, but an alt row alone is not
used to create a design-fixture entry. Its future soft-link behavior remains a
separate investigation.

## Example display contract

Examples are owned by the nearest `.dt`, `.un`, phrase, or related-information
container. The fixture preserves `.mw_t_wi` target highlighting and example
attribution where present.

Each local example group shows one example by default. Additional examples are
inside a collapsed `details` node labelled, for example, `2 more examples`.
This rule applies to both source groups that already have hidden extras and
groups represented as adjacent example nodes.

## Manual fixture coverage

The hand-authored JSON currently demonstrates these recognized units:

- lexical/POS boundaries and WTY-style definition tags;
- pronunciation with multiple readings;
- one-line inflection metadata;
- origin text and origin-section title;
- numbered, lettered, and parenthesized definition structure;
- sense/definition labels, including `substandard`, `slang`, and `obsolete`;
- nested usage notes and examples;
- example source text and target highlighting;
- comparison/cross-reference text and `whoever 1` superscript;
- defined phrase sections, phrase-local alternatives, canonical entries, and
  the `what and if` soft link.

The term bank is intentionally edited directly. `write-zip.ts` only packages
it; no HTML or SQLite parser is involved in this design job.
