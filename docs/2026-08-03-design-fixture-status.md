# MWU → Yomitan design-fixture status

Archived checkpoint: 2026-08-03

This document records the status of the current design-fixture job. It is an
archive of the work completed and the remaining work; it does **not** mean
that the production MWU-to-Yomitan converter is finished.

## Current status

The source reconnaissance and information-unit vocabulary are substantial. A
real-text Yomitan fixture exists, but it is a provisional design experiment,
not a complete or final output design. The selected-word v1 builder is now
implemented and verified, and the fixture does not contain every definition
from every surveyed article.

The current state is therefore:

> **Selected-word v1 implemented and validated; richer conversion remains.**

## What is complete

### Source understanding and documentation

- The SQLite source shape is documented around `word(id, w, m)` and the
  `alt` lookup table.
- The six-level MWU-oriented ownership model is documented.
- Information units are named, explained, connected to observed HTML classes,
  assigned to their nearest semantic owner, and marked as included or ignored.
- `main-canonical-entry`, `alternative-spelling-canonical-entry`,
  `drp-phrase-canonical-entry`, and `soft-link-entry` generation rules are
  documented, including embedded alternative-spelling ownership and
  dedicated-row deferral.
- The general bare-affix rule is documented: for a source-confirmed marked
  prefix, suffix, infix, or marked alternate, remove only the boundary hyphen
  for an additional searchable term and point it to the same canonical target
  with the `alternative` rule. This is a source-assisted rule, not a fixed
  list of `il`, `im`, `ir`, and `ino`.
- User decisions are recorded: no pronunciation audio for now, no First Known
  Use output for now, IPA stays in structured content, one example is visible
  by default, extra examples collapse, phrases collapse by default, and
  phrase alternatives use the `alternative` rule.

### Manual semantic/Yomitan fixture

- The design fixture is hand-authored JSON using real MWU text. It is not the
  final parser data model, final visual contract, or production acceptance
  snapshot, and it is not generated by an HTML parser.
- The fixture contains 136 Yomitan term-bank records.
- The `what` fixture demonstrates independent same-spelling `<mean>` records,
  multiple IPA readings, one-line inflection metadata, scoped labels, nested
  definitions and usage notes, examples, target highlighting, superscript
  references, origin sections, defined phrases, phrase alternatives, source-
  row soft links, and the `what an if` / `what and if` relationship.
- The expanded fixture includes real-text structural slices for `turn`,
  `take`, `run`, `process`, `have`, `set`, `hand`, `give`, `in`, and `o`.
- The `set` slice includes 112 verb senses, 16 adjective senses, 80 noun
  senses, and 29 defined phrases.
- The fixture currently demonstrates `main-to-alternative-spelling-soft-link`
  routes such as:

  - `in` → `in-` and `-in`;
  - `o` → `O`, `o-`, `-o`, `-o-`, `o'`, and `oh`;
  - marked forms `il-`, `im-`, `ir-`, and `ino-` → `in-`;
  - current bare examples `il`, `im`, `ir`, and `ino` → `in-` with the
    `alternative` rule.

### Selected-word v1 builder

- The production CLI accepts explicit `--words` and `--words-file` targets;
  it has no stdin or full-database fallback.
- The source adapter indexes decoded row keys without loading every HTML
  payload, then loads selected roots and dedicated canonical dependencies on
  demand.
- The first version plans `main-canonical-entry`,
  `alternative-spelling-canonical-entry`, and `drp-phrase-canonical-entry`
  owners plus `main-to-alternative-spelling-soft-link`,
  `vr-mean-alternate-soft-link`, `phrase-alternate-soft-link`, and
  source-confirmed `bare-affix-soft-link` routes. Soft links retain
  relationship evidence and never copy a canonical definition.
- Conservative owner-local conversion, tuple validation, deterministic
  reporting, ZIP export, archive schema checks, and browser import are wired
  end to end.

## Problems still open

1. **The full converter is not finished.** v1 is intentionally a conservative
   selected-word owner-local conversion; the design job still does not define
   a complete Level 1-6 semantic parser.
2. **The fixture is incomplete and provisional.** `set` has a frozen
   recognized slice, but `turn`, `take`, `run`, `process`, `have`, `hand`,
   `give`, `in`, and `o` are not complete article transcriptions. Existing
   hierarchy and styling choices may change and do not constrain the first
   production version.
3. **The v1 soft-link generator is intentionally narrow.** It derives the
  approved `main-to-alternative-spelling-soft-link`,
  `vr-mean-alternate-soft-link`, `phrase-alternate-soft-link`, and
  `bare-affix-soft-link` routes from selected HTML/source-row evidence;
  broader relationship families remain future work.
4. **Superscript ownership needs a complete output audit.** Homograph numbers,
   sense references, and cross-reference numbers must remain distinct and be
   attached to their nearest owner.
5. **Line-break behavior needs a complete output audit.** Source block markers
   must become intentional structured-content blocks; ordinary inline labels
   must not acquire accidental line breaks.
6. **Some information units are recognized but not fully settled visually.**
   This includes `.sgram` tag-bank promotion, Level 6
   `.see-in-addition` styling, nested citations, related inline items, and
   called-also reference numbers.
7. **The unknown class inventory needs follow-up.** Images/tables, phrase
   dates, dynamic sense marker classes, and link/style classes must be checked
   against representative source words before parser implementation.
8. **Interposed-object output remains deferred.** Real phrases such as `give
   you up` and `take the word` need broader Yomitan validation before a future
   `v_phr` mapping is implemented.

## Remaining TODO, in order

### 1. Extend the selected-word builder beyond v1

The first selected-word implementation is complete for its documented
boundary. Future work should extend it only after the survey establishes the
additional information units and ownership rules:

- Accept explicit roots through `--words <word...>` and an optional
  newline-delimited `--words-file <path>`; do not read roots from stdin or
  fall back to a full-database build.
- Read the selected source rows and their HTML on demand.
- Create `main-canonical-entry` and `alternative-spelling-canonical-entry`
  records for definition-bearing local `<mean>` elements according to the
  documented ownership rules.
- Create `drp-phrase-canonical-entry` records and the approved
  `main-to-alternative-spelling-soft-link`, `vr-mean-alternate-soft-link`,
  `phrase-alternate-soft-link`, and `bare-affix-soft-link` records.
- Add dedicated dependency rows until every soft-link target is canonical in
  the selected archive.
- Generate `bare-affix-soft-link` records from the confirmed affix shape instead of a
  hardcoded word list.
- Render conservative readable owner-local definitions, write a deterministic
  build report, and export a schema-valid importable ZIP.

### 2. Build the richer semantic renderer after v1

Use production findings and the living survey to implement the complete Level
1-6 semantic model, richer pronunciation and label presentation, examples,
origins, references, and collapsed sections. The hand-authored fixture may
supply examples, but it is not the acceptance oracle for this work.

### 3. Resolve the remaining evidence questions

- Inspect representative words for every unknown class listed above.
- Build the complete `.sgram` value inventory and decide later whether any
  values should become Yomitan tags.
- Verify `.see-in-addition` ownership outside synonym discussions.
- Verify all superscript and line-break shapes in representative HTML.
- Add newly confirmed information units to the catalog before implementing
  their parser behavior.

### 4. Validate the generated dictionary

- Extend the report with future semantic inventories such as
  interposed-object candidates and broader unknown information.
- Import future richer output into Yomitan and verify collapsed sections,
  term order/priority, and rendered ownership beyond the v1 smoke routes.
- Manually inspect representative searches: `what`, `set`, `in`, `o`, `give
  you up`, `take the word`, and a bare affix such as `il`.
